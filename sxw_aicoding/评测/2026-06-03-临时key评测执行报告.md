## 4. 工具链与环境问题

### 4.1 DashScope WebParser 限流

观察到：

```text
HTTP/1.1 429 Too Many Requests
McpError: Connection closed
```

影响：

- `fetch_url` 在 httpbin 简单任务中有时成功，有时限流。
- 任务可能依赖 Python requests 兜底而最终成功，导致“任务成功率”掩盖了工具层失败。
- 若继续跑 `live_web` 或包含大量 fetch 的 suite，结果噪声会很高。

建议：

- 对 `live_web` 降低 repeat，并单独报告。
- 增加 WebParser 调用间隔或并发限制后再重跑。
- 在报告中单独统计 tool error，不只看 task success。

### 4.2 `python` / `python3` 环境不一致

观察到：

- 评测 CLI 必须用 `python3`。
- 任务执行过程中，模型仍会尝试 `python`，失败后再尝试 `python3`。

影响：

- 多文件 / pytest 任务容易浪费 ReAct 迭代。
- `file_multi_001` 失败与该环境适配问题有关。

建议：

- 在系统提示或工具返回中更明确提示“本环境使用 python3”。
- 对评测环境增加 `python -> python3` shim，或把任务提示改为显式使用 `python3`。

### 4.3 EvaluationProbe 兼容性警告

观察到：

```text
[EvaluationProbe] Error handling event 'step_failed': 'Step' object has no attribute 'get'
```

影响：

- 主评测不中断。
- 失败事件采集可能不完整，影响 failure_category 或 step-level 诊断准确性。

建议：

- 优先修复 `EvaluationProbe` 对 `Step` 对象和 dict 的兼容处理。
- 修复后重跑 `file_multi_001` 和 `resume_001` 这类失败任务。
