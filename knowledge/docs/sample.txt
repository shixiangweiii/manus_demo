Manus Agent Architecture Overview

Manus is a local learning project for comparing two explicit agent orchestration
paradigms: a model-driven AgentLoop and structured Plan-and-Execute workflows.

Core Design Principles:
1. AgentLoop: The agent_loop engine keeps one task-level message history. The model
   chooses structured tool calls, receives matching role="tool" results, and repeats
   until it returns final text without another tool call. Planning and reflection are
   internal model behaviors rather than separate runtime stages.

2. Plan-and-Execute: The sequential and dag engines first create explicit plans.
   Sequential execution can reflect and re-plan between actions, while DAG execution
   preserves dependencies and makes concurrency explicit. Their individual actions
   use a bounded native tool-calling loop.

3. Native Tool Calling: Both paradigms use OpenAI-compatible structured tool calls.
   The runtime validates arguments, executes calls in response order, and returns a
   result carrying the matching tool-call ID. It does not require or parse classic
   ReAct text labels such as Thought:, Action:, and Observation:.

4. Isolated Subagents: Any root engine may invoke the subagent tool. A child receives
   its own AgentLoop history, sandbox context, budget, and Todo state; it cannot spawn
   another child, and its final assistant text returns as a normal tool result.

Memory System:
- Short-term Memory: Maintains recent conversation context using a sliding window
  approach. This provides immediate context for ongoing interactions.
- Long-term Memory: Persists task summaries and learnings across sessions. Enables
  the agent to recall past experiences and avoid repeating mistakes.

Context Management:
When conversation history grows too long, the context manager automatically
compresses older messages into concise summaries using the LLM itself. This
preserves important information while staying within token limits.

Knowledge Retrieval:
The agent can access a knowledge base of documents to inform its planning and
execution. Documents are indexed and retrieved based on relevance to the current
task, providing domain-specific context.

Tool System:
Agents can interact with the external world through a pluggable tool system:
- Web Search: Query information from the internet
- Code Execution: Run Python code to perform computations
- File Operations: Read and write files for data processing

The tool system exposes only the capabilities enabled for the current run. AgentLoop
also receives a private todo_write display tool; Todo state does not schedule work or
decide whether the task succeeded.

Reflection and Verification:
Sequential Plan-and-Execute has an explicit reflection and re-planning stage.
AgentLoop relies on the model's ongoing task history and tool observations instead
of adding an external planner or reflector.
